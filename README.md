# 折りたたみ時間

Pixel Fold で、画面を閉じているときと開いているときで、どのアプリをどれだけ使ったかを端末内に記録する個人用アプリです。Play ストアには出しません。ネットワーク権限はなく、記録は外に出ません。

パッケージ名は `io.github.haratak.foldusage` です。

## インストール

1. [Releases](https://github.com/haratak/fold-usage-tracker/releases) から `fold-usage-tracker-vX.Y.Z.apk` をダウンロードする。
2. ファイルアプリで APK を開き、この提供元からのインストールを許可して入れる。
3. アプリの「設定」で、次を順に許可する。
   - 使用状況へのアクセス
   - 通知
   - バッテリー最適化の除外
4. 「記録を開始」を押す。通知に「開閉を記録中」と出ていれば動いています。再起動後も、記録をオンにしたままであれば自動で再開します。

更新するときは、新しい APK を同じ手順で上からインストールします。

## 画面

- **今日 / 7日 / 30日**。今日はその日の 0 時から、端末のタイムゾーンで区切ります。7日と 30日は、今からさかのぼる期間です。
- **閉じてる / 開いてる** ごとに、アプリのアイコン、名前、時間を長い順に出します。合計と割合のバー、開閉の回数も出します。
- 共有ボタンは、いま表示している期間のセッションを CSV にします。列は `start,end,package,app_label,fold_state` です。`fold_state` は `folded` または `unfolded`。時刻は端末のタイムゾーンの ISO-8601 で、Excel で開きやすいよう UTF-8 の BOM を付けています。

## 許可

| 許可 | 用途 |
| --- | --- |
| 使用状況へのアクセス | `UsageStatsManager.queryEvents` で、前面にあったアプリの開始と終了を復元する |
| 通知 | 記録中の常駐通知を出す |
| バッテリー最適化の除外 | 画面オフやバックグラウンドでもサービスが止まりにくくする |

使用状況へのアクセスがないと、開閉の回数は見えてもアプリごとの時間は出ません。

## 開閉の判定

フォアグラウンドサービスが、アプリが前面にいなくても開き具合を見続け、変化を時刻つきで Room に保存します。通知は低優先度で、消せない常駐通知です。

判定には **DisplayManager のディスプレイリスナー** を使います。Pixel 10 Pro Fold では外側と内側が別の内蔵ディスプレイで、使っている側だけが点灯します。点灯中の内蔵ディスプレイの物理ピクセルの長辺÷短辺が **1.6 以上なら閉じてる、未満なら開いてる** です。API 37 以降は `Display.isInternal()` で内蔵ディスプレイに絞ります。それより前の公開 SDK には `getType()` が残っていないため、プレゼンテーション表示でもプライベート表示でもないディスプレイを内蔵とみなします。

- 外側（カバー）: 1080×2364、約 2.19 → 閉じてる
- 内側: 2076×2152、約 1.04 → 開いてる

回転では物理ピクセルの縦横が入れ替わらないので、向きでは変わりません。画面オフは `ACTION_SCREEN_OFF` / `ACTION_SCREEN_ON` と `PowerManager.isInteractive()` で別枠にし、オフの時間は合計に入れません。サービスは約 30 秒ごとに状態を再確認します。

Jetpack WindowManager は Activity のウィンドウに紐づき、アプリが前面にないあいだ更新が止まるため使っていません。`DeviceStateManager` は API 36 の時点でも公開 SDK に入っておらず（`@hide` / `@TestApi`、開発者向けリファレンスもない）、隠し API 経由では通常のアプリから安定して呼べないため使っていません。

## 制限

実機で確認が必要な点があります。

- 折りたたみ、展開、画面オフのときに、どのディスプレイ ID が `STATE_ON` になるか。サイズが想定と違う場合、設定画面の「閉じてる（1080×2364）」のような表示で分かります。
- アプリを閉じたまま、折りたたんでもリスナーが届くか。
- 半分開き（テーブルトップ）は、内側が点灯していれば「開いてる」になります。
- 切り替えの瞬間に両方の画面が点灯すると、面積の大きい内側を優先します。
- 画面オフのあいだに折ると、次に画面が点くまで直前の開閉のままです。オフの時間はアプリ使用時間に入らないので、使用時間のずれは小さい想定です。
- サービスが殺されていた時間は、最後に生きていた時点（最大で約 90 秒前）までしか数えません。バッテリー最適化を除外すると止まりにくくなります。
- アプリの使用時間は OS の使用状況イベントに依存します。ごく短い前面表示は欠けることがあります。
- 縦横比で分けているので、外側がほぼ正方形の端末や、内側がとても縦長の端末では取り違えます。このアプリは Pixel Fold 系を想定しています。
- 端末の時計を大きく変えると、使用状況との対応がずれることがあります。

## 開発

```bash
./gradlew lint test assembleRelease
```

minSdk 31、compileSdk 37.2、targetSdk 37。署名用キーストアはリポジトリに含めません。

GitHub Actions（`.github/workflows/android.yml`）は、main への push と pull request で lint、ユニットテスト、`assembleRelease` を実行し、APK をワークフローのアーティファクトに上げます。タグ `v*` では、同じビルドの APK を `fold-usage-tracker-vX.Y.Z.apk` として GitHub Release に添付します。`versionCode` は `GITHUB_RUN_NUMBER` です。

署名はリポジトリシークレット `KEYSTORE_BASE64`（PKCS12 を base64）、`KEYSTORE_PASSWORD`、`KEY_ALIAS`（`release`）、`KEY_PASSWORD` です。ビルド時だけデコードし、シークレットが無いときは debug 署名に落としてビルドを失敗させません。シークレットがある場合、`apksigner verify --print-certs` の SHA-256 が次と一致することを確認します。

`3F:EF:3B:69:23:0C:16:96:C4:FC:16:4F:73:2D:56:3E:1B:B9:6F:82:70:D3:FD:FD:50:AB:35:9C:F1:02:5E:44`
